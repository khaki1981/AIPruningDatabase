# データベース運用方針

1. 書籍に明記された内容を優先する。
2. AIの一般知識を無断で補わない。
3. 本文、表、カレンダー、図、メモを区別する。
4. 推測が必要な内容はJSONへ確定登録しない。
5. 別資料で内容が一致した場合は `sources` に出典を追加する。
6. 別資料で内容が異なる場合は上書きせず、条件や出典を分けて記録する。
7. 品種や系統で剪定方法が異なる場合は、別の植物データとして登録する。
8. 書籍の挿絵をそのまま転載せず、意味を整理した独自SVGとして再構成する。
9. すべての植物データはSchema検証を通す。
10. `reviewStatus` が `verified` になるまでは公開用データとして扱わない。
11. `appliesTo` を省略した剪定方法・図解は、そのJSONの植物だけに適用されるものとして扱う。
12. 複数植物に適用される剪定方法・図解だけに `appliesTo` を使用する。
13. `grafted-on` は「このレコードの植物が、`targetPlantId` の植物を台木としている」という方向で記録する。
14. 未登録の `targetPlantId` と `targetId` は当面許可する。
15. 未登録参照はSchemaエラーとせず、検証時の警告として扱う。
16. 植物間の関係や情報の適用対象を、AIの一般知識から補完しない。
17. 空の `appliesTo` 配列は使用せず、単独植物だけに適用する場合は `appliesTo` 自体を省略する。
18. 2種類以上の植物が同じページに掲載されている場合、カレンダーやグラフを自己判断で各植物に割り当てない。どの帯がどの植物に対応するか不明な場合、特に複数植物の線や帯が重なっている場合は推測せず、JSONを作成・修正する前にユーザーへ確認する。
19. カレンダーの帯の開始・終了が上旬・中旬・下旬に見える場合、月全体として断定しない。「上旬に見える」「中旬に見える」などの読み取り候補を報告してユーザーへ確認し、確認が終わるまで推測でJSONへ登録しない。
20. 画像の読み取りに確信が持てない場合は一般知識で補完せず、該当する植物名、ページ、項目、読み取り候補を報告してユーザーの判断を待つ。
21. 忌み枝・切るべき枝の定義と基本的な剪定方法は、植物JSONから分離し、植物間で共通利用できるデータとして管理する。
22. 書籍画像から忌み枝データを作成する場合は、本文・図・写真・キャプションを区別し、読めない内容や欠落ページを一般知識で補完しない。
23. 忌み枝データに記録された一般的な説明を、出典なしに個別植物へ適用しない。植物ごとの適用可否は別途、出典に基づいて関連付ける。
